# 数据与隐私

[返回项目首页](../README.md)

SATLI 以本地处理为主。扫描、编辑、备份和恢复均在当前 Windows 用户的设备上完成。

## 本地数据

默认数据目录为：

```text
%LOCALAPPDATA%\SATLI\
```

其中可能保存：

- 应用设置和窗口位置
- 游戏名称与云端列表缓存
- 已校验的翻译 JSON，以及发往 lite 的请求与状态跟踪记录
- 安装、编辑和恢复历史
- 编辑草稿、原文件备份与强制恢复归档
- JSON 工程的来源、获取时间、原文快照与人工草稿，以及分开保存的 AI 待审结果
- 用户启用的诊断日志

本地编辑不会自动把本机 schema 上传到网络。应用不会主动清理此目录中的数据。

独立翻译 JSON 导出在本机完成，可包含尚未写回 Steam 的草稿内容。导出会保留源文件中的语言文本，不改变 Steam BIN、备份或修订记录，也不会自动向 SATLI-lite 发送数据或上传投稿附件。

扫描、预览和翻译管理的命令核心直接在 SATLI 应用进程内运行。需要写入受保护 Steam 目录时，会请求用户确认 UAC。

## 凭据

可选的 Steam Web API Key、AI API Key 和自定义代理密码使用 Windows DPAPI CurrentUser 加密保存，仅当前 Windows 用户能够解密。AI 设置提供“清除密钥”；更换 AI 服务地址或接口类型时不会沿用原密钥。

## 网络请求

应用会根据用户使用的功能连接以下服务：

- **翻译目录和译本：** 按用户设置向 jsDelivr（含 Fastly 域名）、GitHub Raw、StaticDelivr 请求 V2 翻译目录并在需要时回退 V1，再从配置的文件源下载经 SHA-256 校验的译本
- **软件更新：** 独立安装版通过 GitHub 获取更新信息和发布包
- **SATLI-lite 安装：** 用户从设置中的独立管理入口或 JSON 应用流程确认安装后，从 SATLI-lite 官方 GitHub 最新正式 Release 下载插件；已有安装原样保留，但不会检查更新
- **安装运行库：** 独立安装器仅在检测到缺少运行库时，从微软官方域名下载 .NET 10 Desktop Runtime 和 Windows App Runtime 安装程序
- **Steam 游戏库：** 用户主动配置凭据后，通过 Steam Web API 补全账号游戏库
- **游戏名称：** 通过游戏名称数据源补全 App ID 对应的名称
- **公开成就：** 用户创建工程时匿名请求 Steam 公开成就页面和商店游戏名称
- **AI 翻译：** 用户确认后，将游戏名、App ID、成就 API ID 和实际可用的多语言文本发送到其配置的 AI 服务；不发送完整 Steam 凭据或无关本机文件。模型测试发送固定测试文本。调用和可选搜索可能产生费用，服务商的数据处理适用其自身条款
- **问题报告、翻译请愿和投稿：** 用户主动操作时，在默认浏览器中打开预填的 GitHub Issue 草稿或表单

## 诊断日志

日志不会记录 Steam Web API Key、代理密码、成就文件正文、用户填写的问题说明或请愿备注，也不会记录带预填查询参数的 GitHub Issue 地址。

AI 日志只记录操作、目标语言、数量和安全的结果摘要，不记录密钥、请求、回复正文或思考摘要。界面临时展示服服商提供的思考文本或摘要，不持久保存；参考网站与待审结果在本机分别保存。工程日志记录创建、保存、来源准备、取消和失败摘要。

日志可以关闭，并分为以下级别：

- **基础：** 记录启动与设置、扫描与缓存、安装与恢复、本地导入、编辑与草稿、修订与 BIN/ZIP/JSON 导出、Steam 进程保护、网络与更新、JSON 下载校验、本地译文发送、lite 安装与连接及排队/接收/处理结果、翻译目录 V1 回退或离线降级、GitHub 表单准备等功能的关键开始、结果、用户取消、警告和错误摘要。
- **详细：** 在基础日志上增加翻译目录版本与缓存状态、App ID、游戏名、目标语言、项目数量、文件名、界面资源加载结果、逐项处理事件、后台预加载与并行扫描准备耗时、异常类型和 HRESULT，适合排查具体游戏或操作。
- **Debug（本次运行）：** 在详细日志上增加设置参数、命令核心事件摘要与标准错误、耗时、完整路径、完整异常堆栈和运行环境。事件摘要不包含成就或译文正文。关闭并重新打开应用后会自动恢复为“详细”。

详细和 Debug 日志可能包含本机目录、Steam 路径、App ID、游戏名和文件诊断信息，体积也会明显增大。向他人发送日志前，请先检查并删除不希望分享的内容。

## 文件保护

应用在写入前创建备份。若目标文件之后被 Steam 或其他程序修改，普通恢复会拒绝覆盖；强制恢复也会先归档当前文件，再恢复原备份。

这些保护用于减少误覆盖风险，但不能代替重要数据的额外备份。

## SATLI-lite 本机接口

用户确认应用 JSON 后，SATLI 向 Steam 目录中的 `millennium\config\satli-lite\external\v1` 原子投递请求。请求包含 App ID、Variant、目标语言、成就 API name 及译文。SATLI 不直接修改 lite 的私有状态或译本。

JSON 管理页还会读取 lite 在 `external\v2` 发布的公开译文清单与当前译文快照，以列出已安装内容并创建可编辑草稿。此接口只读；打开与保存本地草稿不会修改 lite 的数据。快照由 lite 在本机保留，可能落后于 Steam 当前状态。

这些数据保存在本机，不上传到 SATLI 或第三方服务器。SATLI 数据目录也保留原始请求字节与最近一次导入记录，以便超时、取消等待或重启后追踪原请求；插件回执和结果持久保留。SATLI 无需常驻。

用户也可主动发送编辑器当前目标语言文本，或将本地 BIN/ZIP 转换后发送。保存草稿、写回 BIN、恢复和导出均不会自动发送；lite 中的编辑不会反向覆盖桌面端草稿。Steam 关闭或插件暂不可用时，经确认的请求可以留在本机队列中等待，默认拒绝覆盖 lite 已有译本。

如果 SATLI 未检测到 Millennium，只有在用户点击“打开 Millennium 官方安装页”后，SATLI 才会让系统浏览器访问 Steam Homebrew 官方文档。SATLI 不会下载、内置或代为运行 Millennium 安装器。

旧显示桥迁移由用户单独确认，在 Steam 退出后只将 `millennium/plugins/satli.star` 移入 Windows 回收站。该操作不清理 `satli-bridge-v1.json`、lite 私有数据、本地译文或 BIN 备份；回收不可用时停止。
