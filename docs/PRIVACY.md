# 数据与隐私

[返回项目首页](../README.md)

SATLI 以本地处理为主。扫描、编辑、备份和恢复均在当前 Windows 用户的设备上完成。

## 本地数据

默认数据目录为：

```text
%LOCALAPPDATA%\SATLI\
```

其中可能保存：

- 应用设置和窗口位置
- 游戏名称与云端列表缓存
- 已校验的翻译 JSON，以及发往 lite 的请求与状态跟踪记录
- 安装、编辑和恢复历史
- 编辑草稿、原文件备份与强制恢复归档
- 用户启用的诊断日志

本地编辑只修改选择的目标语言，不会自动把本机 schema 上传到网络。应用本身不会因切换 Microsoft Store、独立安装版渠道而主动清理此目录中的数据。

扫描、预览和翻译管理的命令核心直接在 SATLI 应用进程内运行。需要写入受保护 Steam 目录时，会在用户确认 UAC 后启动一个 SATLI 管理员工作进程，并通过仅限当前用户和管理员的本机命名管道传递本次请求。

## 凭据

可选的 Steam Web API Key 和自定义代理密码使用 Windows DPAPI CurrentUser 加密保存，仅当前 Windows 用户能够解密。

## 网络请求

应用会根据用户使用的功能连接以下服务：

- **翻译目录和译本：** 按用户设置向 jsDelivr（含 Fastly 域名）、GitHub Raw、StaticDelivr 请求 V2 翻译目录并在需要时回退 V1，再从配置的文件源下载经 SHA-256 校验的译本
- **软件更新：** Microsoft Store 版由 Microsoft Store 管理；独立安装版通过 GitHub 获取更新信息和发布包
- **SATLI-lite 安装：** 用户选择 JSON 应用并确认安装后，从 SATLI-lite 官方 GitHub 正式 Release 下载插件，按发布资产的大小及完整性元数据校验；不覆盖已安装插件的设置和译本
- **安装运行库：** Microsoft Store 版由 Store 获取 Windows App Runtime 共享框架；独立安装器仅在检测到缺少运行库时，从微软官方域名下载经 SHA-256 校验的 .NET 10 Desktop Runtime 和 Windows App Runtime 安装程序
- **Steam 游戏库：** 用户主动配置凭据后，通过 Steam Web API 补全账号游戏库
- **游戏名称：** 通过游戏名称数据源补全 App ID 对应的名称
- **问题报告、翻译请愿和投稿：** 用户主动操作时，在默认浏览器中打开预填的 GitHub Issue 草稿或表单

打开文件报告草稿时，预填正文只包含游戏名、App ID、问题类型、用户填写的说明和可选参考来源。GitHub 目前无法可靠地通过 URL 预选 Issue Form 下拉框，因此 SATLI 使用结构化正文保留问题类型；请愿和投稿仍使用表单，只预填已确定的游戏、语言、摘要等文本字段。ZIP 不会被自动上传，最终内容和附件由用户在浏览器中检查并提交。

## 诊断日志

日志不会记录 Steam Web API Key、代理密码、成就文件正文、用户填写的问题说明或请愿备注，也不会记录带预填查询参数的 GitHub Issue 地址。

日志可以关闭，并分为以下级别：

- **基础：** 记录启动与设置、扫描与缓存、安装与恢复、本地导入、编辑与草稿、修订与导出、Steam 进程保护、网络与更新、JSON 下载校验、lite 安装与连接及请求状态、翻译目录 V1 回退或离线降级、GitHub 表单准备等功能的关键开始、结果、用户取消、警告和错误摘要。
- **详细：** 在基础日志上增加翻译目录版本与缓存状态、App ID、游戏名、目标语言、项目数量、文件名、逐项处理事件、后台预加载与并行扫描准备耗时、异常类型和 HRESULT，适合排查具体游戏或操作。
- **Debug（本次运行）：** 在详细日志上增加设置参数、命令核心事件摘要与标准错误、耗时、完整路径、完整异常堆栈和运行环境。事件摘要不包含成就或译文正文。关闭并重新打开应用后会自动恢复为“详细”。

详细和 Debug 日志可能包含本机目录、Steam 路径、App ID、游戏名和文件诊断信息，体积也会明显增大。向他人发送日志前，请先检查并删除不希望分享的内容。

## 文件保护

应用在写入前创建备份。若目标文件之后被 Steam 或其他程序修改，普通恢复会拒绝覆盖；强制恢复也会先归档当前文件，再恢复原备份。

这些保护用于减少误覆盖风险，但不能代替重要数据的额外备份。

## SATLI-lite 本机接口

用户确认应用 JSON 后，SATLI 向 Steam 目录中的 `millennium\config\satli-lite\external\v1` 原子投递请求。请求包含 App ID、Variant、目标语言、成就 API name 及译文。SATLI 只使用 lite 的公开请求、回执、结果和心跳文件，不直接修改 lite 的私有状态或译本。

这些数据保存在本机，不上传到 SATLI 或第三方服务器。SATLI 数据目录也保留请求副本，以便超时后追踪原请求；插件回执和结果持久保留。已投递不代表导入完成，已启用也不代表页面已渲染。SATLI 无需常驻。旧 `satli-bridge-v1.json` 不再写入或刷新，旧快照与 BIN 备份不会在迁移时被静默清理。

如果 SATLI 未检测到 Millennium，只有在用户点击“打开 Millennium 官方安装页”后，SATLI 才会让系统浏览器访问 Steam Homebrew 官方文档。SATLI 不会下载、内置或代为运行 Millennium 安装器。
